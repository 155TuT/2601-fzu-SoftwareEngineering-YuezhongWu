# 校园失物招领小程序产品需求文档（PRD）

本文档用于约定产品范围、页面内容、交互规则和验收标准，为本次原型设计及后续结对编程提供依据。

## 背景与问题

校园内遗失或捡到校园卡、钥匙、水杯、雨伞、耳机、书籍等物品后，同学通常在班级群、宿舍群或朋友圈发布信息。这些渠道覆盖范围有限，消息容易被新内容淹没，失主与拾物者即使在同一校园内，也未必能看到彼此的信息。

根据客户描述，本产品需要解决三个问题：

- **信息分散**：建立统一入口，集中展示寻物与招领信息。
- **查找不便**：通过物品名称搜索，并区分寻物与招领两种信息。
- **处理进度不清楚**：物品找回或归还后，由发布者更新状态，减少无效查找和重复联系。

## 用户与使用场景

### 主要用户

| 用户角色 | 使用情境 | 核心需求 |
| -------- | -------- | -------- |
| 失主 | 在校园内遗失物品，希望尽快找回 | 搜索已有招领信息；发布寻物信息；找到匹配信息后联系发布者 |
| 拾物者 | 捡到物品，但不知道如何联系失主 | 快速发布招领信息，说明物品特征和拾取地点；归还后更新状态 |
| 浏览者 | 帮同学寻找物品，或偶然发现匹配信息 | 看懂信息类型，按名称查找并查看详情 |

### 典型场景

| 编号 | 场景 | 期望结果 |
| ---- | ---- | -------- |
| S01 | 学生在图书馆遗失一把雨伞，进入小程序搜索“雨伞” | 在招领结果中查看颜色、时间和地点，找到可能匹配的信息并获取联系方式 |
| S02 | 学生在教学楼捡到钥匙，没有找到相关寻物信息 | 发布一条招领信息，让失主能够通过“钥匙”搜索到它 |
| S03 | 学生搜索后未发现自己的水杯 | 保留清楚的无结果提示，并可前往发布寻物信息 |
| S04 | 双方联系并完成物品交接 | 发布者将寻物标记为“已找回”，或将招领标记为“已归还” |

## 产品目标与范围

### 产品目标

让学生完成“发现信息—查看详情—联系发布者”和“发布信息—等待联系—更新状态”两条基本流程。首页应能直接进入浏览、搜索和发布，用户无需理解复杂的操作概念。

本次原型的目标是让演示者能够独立完成以下任务：

1. 从首页打开一条信息，判断其类型、状态及物品特征。
2. 分别发布一条寻物信息和一条招领信息，并看到明确的成功反馈。
3. 输入物品名称，查看匹配结果或无结果反馈。
4. 在有效信息详情中找到发布者的联系方式。
5. 从“我的发布”进入自己的信息，确认完成并看到状态更新。

### 设计范围

首版包含首页、发布信息、搜索、信息详情、“我的发布”五类页面，以及发布成功、表单错误、空结果、完成确认等必要状态。寻物与招领共用发布页面，通过信息类型切换字段文案。

| 范围 | 内容 |
| ---- | ---- |
| 核心功能 | 浏览、发布寻物、发布招领、按名称搜索、查看详情与联系方式、查看自己的发布、更新完成状态 |
| 基本展示 | 物品名称、类型、类别、时间、地点、描述、可选图片、联系方式、处理状态 |
| 本次交付形式 | 需求文档、流程图和可点击原型 |

联系和物品交接不属于产品范围，由双方在线下或已有通信工具中完成，小程序仅提供信息和联系方式，不判断物品归属，也不将“查看联系方式”视为找回或归还成功。

## 功能需求

| 编号 | 功能 | 需求说明 | 主要验收点 |
| ---- | ---- | -------- | ---------- |
| F01 | 浏览信息 | 首页展示仍在处理中的寻物、招领信息；支持“全部\/寻物\/招领”切换 | 类型标签清楚，切换后列表符合条件，点击卡片可进入对应详情 |
| F02 | 发布寻物 | 选择“寻物”，填写遗失物品、遗失时间、遗失地点和联系方式 | 必填项校验通过后显示发布成功，新信息状态为“寻找中” |
| F03 | 发布招领 | 选择“招领”，填写捡到的物品、拾取时间、拾取地点和联系方式 | 必填项校验通过后显示发布成功，新信息状态为“待认领” |
| F04 | 搜索物品 | 按物品名称关键词搜索，可切换信息类型 | 返回匹配的有效信息；无匹配时给出空结果提示 |
| F05 | 查看详情与联系 | 展示完整物品信息，有效信息可展开联系方式 | 从列表与搜索结果进入相同的信息详情，可返回原入口 |
| F06 | 我的发布 | 集中展示当前用户发布的全部信息，包括已完成信息 | 能区分各状态，并进入自己的信息详情 |
| F07 | 更新状态 | 发布者将自己的信息标记为已找回或已归还 | 确认后同步更新详情和我的列表，首页及搜索不再展示该信息 |

## 页面结构与交互

### 页面导航

```text
首页
├─ 信息卡片 → 信息详情 → 展开联系方式
├─ 搜索入口 → 搜索页面 → 搜索结果 → 信息详情
├─ 发布入口 → 发布信息 → 发布成功 → 查看本条详情／返回首页
└─ 我的发布 → 自己的信息详情 → 确认完成 → 已完成状态
```

一级导航采用“首页／发布／我的”三个入口。“发布”打开发布表单，“我的”页面需要在后续补齐个人资料中心。搜索和详情属于二级页面，提供明确的返回入口。

### P01：首页

- 顶部显示产品名称“校园失物招领”和搜索入口，搜索提示为“搜索物品名称，如钥匙、雨伞”。
- 搜索入口下方显示“全部／寻物／招领”切换项，默认选择“全部”。
- 信息卡片显示图片或默认占位图、物品名称、类型、状态、遗失或拾取地点、事件日期；不在卡片上展示联系方式。
- 列表按发布时间从新到旧排列，仅显示“寻找中”和“待认领”的信息。
- 点击卡片进入详情；返回后保留原有类型选择和浏览位置。
- 列表为空时显示“暂时没有相关信息”，并提供“发布信息”入口。

### P02：发布信息

- 顶部选择“寻物／招领”，默认选择“寻物”，当前选项应清楚可见。
- 选择“寻物”时使用“遗失时间、遗失地点、物品特征”等文案；选择“招领”时使用“拾取时间、拾取地点、物品特征”等文案。
- 两种类型共用一份表单；切换类型保留已填写内容，并提示检查时间、地点是否符合当前类型。
- 表单字段、必填规则和图片限制见第 6 节。
- 点击“发布”时校验内容；校验失败保留输入，在对应字段附近提示问题，并定位到首个错误。
- 发布过程中显示“发布中…”，暂时禁用重复提交；失败时保留内容并允许重试。
- 发布成功后显示明确的成功页或成功面板，提供“查看详情”“返回首页”两个入口；本条信息同时出现在首页相应类型和“我的发布”中。
- 在已有输入时主动返回，提示“离开后本次填写内容将丢失”，提供“继续填写”和“放弃填写”；本版不保存草稿。

### P03：搜索

- 提供关键词输入框、搜索按钮及“全部／寻物／招领”切换项。从首页进入时继承首页当前选择的类型。
- 用户点击搜索按钮或键盘搜索键后才提交查询，不要求实时搜索。
- 去除关键词首尾空白后，按物品名称进行包含匹配；英文字母不区分大小写。本版不包含描述全文搜索、拼音搜索或模糊纠错。
- 输入为空或全部为空白时，提示“请输入物品名称”，不执行查询。清空输入后恢复未搜索状态。
- 搜索仅返回仍在处理中的信息，结果按发布时间从新到旧排列。查询后切换类型时，保留关键词并更新结果。
- 无结果时显示“未找到相关物品”，提示更换关键词，并提供“发布寻物”入口；该入口打开空白寻物表单，不自动代填内容。
- 打开详情再返回时，保留关键词、信息类型和结果列表位置。

### P04：信息详情

- 显示物品名称、寻物或招领标签、状态、类别、图片、描述、遗失或拾取时间与地点、发布时间。
- 有效信息显示“查看联系方式”按钮，点击后展开发布者填写的联系方式，并提示“请双方核对物品特征后再约定交接”。
- 联系方式展开不改变信息状态，不创建聊天会话，也不要求填写认领申请。
- 当前用户是发布者时，额外显示“标记为已找回”或“标记为已归还”；他人的信息不显示管理按钮。
- 点击完成按钮后进行二次确认，说明完成后该信息将退出首页和搜索结果；取消时状态不变。
- 已完成详情显示“已找回”或“已归还”，隐藏联系方式入口和管理按钮；之前已展开的联系方式也应收起。
- 若信息无法读取，显示“暂时无法查看这条信息”，提供重试及返回入口，不展示错误的物品内容。

### P05：我的发布

- 展示当前用户发布的寻物与招领信息，包含处理中和已完成状态，按发布时间从新到旧排列。
- 卡片显示物品名称、信息类型、状态、地点和事件日期，点击后进入详情。
- 没有发布记录时显示“你还没有发布过信息”，并提供“去发布”入口。
- 状态管理统一在详情页完成，避免同一操作出现多种含义不同的入口。

## 信息字段与业务规则

### 发布表单

| 字段 | 是否必填 | 规则 | 页面说明 |
| ---- | -------- | ---- | -------- |
| 信息类型 | 是 | “寻物”或“招领”，单选 | 决定时间、地点的文案及初始状态 |
| 物品名称 | 是 | 1—30 个字符 | 建议填写“黑色雨伞”等明确名称，避免只填“求助” |
| 物品类别 | 是 | 校园卡、钥匙、水杯、雨伞、耳机、书籍、其他；单选 | 默认未选择，供阅读辨认；本版不增加类别筛选入口 |
| 遗失／拾取日期 | 是 | 选择有效日期，不晚于发布当天 | 精度到日期；不确定时填写最近一次确认遗失或拾取的日期，并在描述中说明 |
| 遗失／拾取地点 | 是 | 1—50 个字符 | 填写教学楼、食堂、图书馆等文字地点，不接入地图 |
| 物品描述 | 否 | 1—300 个字符 | 描述颜色、外观、发现经过等 |
| 物品图片 | 是 | 最多 1 张，JPG 或 PNG，不超过 5 MB | 可预览发布效果和替换 |
| 联系方式 | 是 | 1—50 个字符 | 填写一种联系方式并注明渠道，如微信、QQ 或电话 |

发布前应提示：“联系方式将向查看此信息的同学展示；请勿公开证件完整号码，图片中的个人信息请先遮挡。”该提示是人工填写提醒，产品不具备自动识别或自动遮挡能力。

### 自动记录的信息

每条信息需要有唯一标识、发布者标识、发布时间和当前状态；完成后记录完成时间。这些信息用于区分记录、确定管理权限、排序和展示，不要求用户在表单中手工填写，也不作为页面中的技术说明展示。

发布时间用于列表排序；遗失或拾取日期用于描述事件发生时间，两者不能混用。

### 状态规则

| 信息类型 | 发布成功后的状态 | 发布者操作 | 完成后的状态 |
| -------- | ---------------- | ---------- | ------------ |
| 寻物 | 寻找中 | 标记为已找回 | 已找回 |
| 招领 | 待认领 | 标记为已归还 | 已归还 |

- 只有发布者可以变更自己信息的状态，取消确认或保存失败时维持原状态。
- 保存成功后，详情和“我的发布”显示新状态；首页和搜索结果移除该条信息，返回旧列表时也应更新。
- 已完成信息仍可从“我的发布”查看；若用户停留在此前打开的详情中，应看到完成提示并收起联系方式。
- 本版只设计“处理中→已完成”的单向变化，不提供恢复、删除或自动过期。

### 用户身份与原型边界

本次原型用固定的“当前用户”和其他示例发布者演示归属关系，暂不增加注册与登录页面。后续代码实现前需确定身份识别方式，并在处理状态变更时验证发布者身份；原型中隐藏按钮只表达可见性规则，不构成权限校验。

## 核心用户流程

### 浏览与联系

```text
进入首页 → 选择信息类型 → 浏览列表 → 点击信息卡片 → 查看详情
                                                   ├─ 信息有效 → 展开联系方式 → 自行联系并核对物品
                                                   └─ 信息已完成 → 查看完成提示 → 返回继续查找
```

### 发布信息

```text
进入发布页面 → 选择寻物／招领 → 填写信息 → 点击发布 → 表单校验
                                                    ├─ 不通过 → 显示字段错误 → 修改后重新提交
                                                    └─ 通过 → 发布中
                                                              ├─ 失败 → 保留内容 → 重试
                                                              └─ 成功 → 发布成功反馈
                                                                        ├─ 查看本条详情
                                                                        └─ 返回首页
```

### 搜索物品

```text
进入搜索页面 → 输入物品名称 → 点击搜索
                              ├─ 空关键词 → 提示输入物品名称
                              └─ 有效关键词 → 显示结果
                                              ├─ 有匹配 → 查看详情 → 展开联系方式
                                              └─ 无匹配 → 更换关键词／发布寻物
```

### 完成与状态更新

```text
双方自行核对并完成交接 → 发布者进入我的发布 → 打开对应详情 → 点击标记完成
                                                        ├─ 取消 → 保持原状态
                                                        └─ 确认 → 保存状态
                                                                  ├─ 失败 → 提示重试，状态不变
                                                                  └─ 成功 → 显示已找回／已归还
                                                                            → 更新我的发布
                                                                            → 首页和搜索移除该条
```

## 异常状态与界面要求

| 情形 | 用户可见反馈 | 后续操作 |
| ---- | ------------ | -------- |
| 必填项缺失或超长 | 在对应字段下说明问题，保留其他内容 | 修改后再次发布 |
| 图片格式或大小不符合要求 | 显示“请选择不超过 5 MB 的 JPG 或 PNG 图片” | 重新选择，或移除图片后继续 |
| 图片加载失败 | 显示占位图，其他文字信息正常可读 | 继续查看详情 |
| 首页暂无信息 | 空列表说明和发布入口 | 切换信息类型或发布 |
| 搜索没有匹配 | 保留关键词与类型，显示无结果说明 | 修改关键词或发布寻物 |
| 列表读取失败 | 明确的加载失败提示，不混同于没有信息 | 点击重试 |
| 发布或状态保存失败 | 提示失败；不显示成功结果，不提前改变状态 | 保留填写内容或原状态，允许重试 |
| 已完成的信息仍被打开 | 展示最新完成状态并收起联系方式 | 返回列表继续查找 |

原型按手机竖屏设计，以 390 × 844 的画板为主要演示尺寸。正文建议不小于 14 px，主要按钮的点击区域建议不小于 44 × 44 px，这些数值作为本稿的设计目标。

寻物、招领及处理状态必须有文字标签，不只靠颜色区分。发布成功、保存失败和状态完成均使用明确文字反馈。

## 原型制作说明

### 必备画面

| 页面编号 | 页面或状态 | 需要展示的内容 |
| -------- | ---------- | -------------- |
| P01 | 首页 | 全部列表、寻物／招领切换、空列表、读取失败 |

## 验收标准

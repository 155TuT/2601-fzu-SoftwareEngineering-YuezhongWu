# 软件工程课程第二次个人作业

作业提交期限（Deadline）：2026-09-22 23:59:59

作业题目：利用 AIGC 完成“一箭又一箭”小游戏

## 作业要求

### 背景

以“羊了个羊”“抓大鹅”等为代表的休闲小游戏，凭借规则简单、操作方便、单局时间短等特点获得了较高关注。这类游戏的核心玩法并不复杂，却包含了界面设计、交互处理、游戏状态管理和算法实现等内容，适合作为一次小型软件开发实践。

“一箭又一箭”是一类点击式箭头解谜游戏。玩家需要观察箭头的方向和相互阻挡关系，按照合适的顺序点击箭头，使所有箭头依次飞出棋盘。其规则容易理解，但在实现过程中需要处理二维坐标、方向判断、路径检测、碰撞反馈和关卡状态等问题。

随着 AIGC 技术的发展，DeepSeek、Kimi、CodeGeeX、Trae、ChatGPT、Codex、GitHub Copilot 等工具已经能够参与需求分析、代码编写、程序调试和界面设计。本次作业希望大家借助 AIGC 工具完成小游戏开发，同时通过实际运行和测试，对 AI 给出的代码进行判断、修改和完善。

### 作业描述

请使用 Python 独立开发一个“一箭又一箭”风格的小游戏。图形界面可以使用 Pygame、Pygame Zero、Tkinter 或其他 Python 图形库完成。

原游戏可参考：微信小游戏《一箭又一箭》。本作业只参考其核心玩法，不要求使用原游戏的素材、代码或关卡。

游戏棋盘中包含若干带方向的箭头，箭头方向分为上、下、左、右四种。玩家点击某个箭头后，程序检查该箭头前进方向上的路径：

如果箭头与棋盘边界之间没有其他箭头阻挡，该箭头飞出棋盘并被消除；
如果路径上存在其他箭头，该箭头不能被消除，并通过移动后返回、晃动、变色或文字等方式提示碰撞；
点击被阻挡的箭头会消耗一次失误机会；
清除本关全部箭头后即可进入下一关；
失误次数耗尽时，本关失败，可重新开始。
本次作业只要求实现上述基础点箭头玩法，无需加入额外机关或复杂玩法。为了统一判定，基础版采用网格中的单格箭头，路径检测只需判断同一行或同一列、箭头与边界之间是否还有其他箭头。

例如：

```text
→  ·  ·  ↑  ·
```

第一个箭头朝右，但它的右侧仍有其他箭头，因此不能飞出。

```text
↑  ·  ·  ·  →
```

最后一个箭头朝右，右侧没有其他箭头，因此可以飞出棋盘。

本次作业必须使用至少一种 AIGC / Coding Agent 工具辅助开发。AI 生成代码的比例不作限制，但提交者需要保证程序能够运行，并基本理解自己提交的代码。

### 任务要求

#### 1.游戏基本要求

程序至少应实现以下功能：

- 具有可以正常显示和操作的图形化游戏界面；
- 棋盘中包含上、下、左、右四种方向的箭头；
- 能够通过鼠标点击选择箭头；
- 能够正确判断箭头前进方向上是否存在其他箭头；
- 前方无阻挡时，箭头能够飞出棋盘并消失；
- 前方有阻挡时，箭头不能消失，并给出明显的碰撞反馈；
- 设置失误次数，并在界面中显示剩余次数；
- 至少设计 3 个可以正常通关的关卡；
- 清空当前关卡全部箭头后，能够显示通关结果并进入下一关；
- 失误次数耗尽时，能够显示失败结果；
- 提供重新开始功能，使当前关卡恢复到初始状态。
- 每个关卡都应由本人实际试玩，确保存在合理的通关顺序。

#### 2.游戏界面

游戏至少应包含：

- 开始界面；
- 游戏界面；
- 通关或失败界面。
- 游戏界面至少显示：
  - 当前关卡；
  - 游戏棋盘；
  - 剩余箭头数量；
  - 剩余失误次数；
  - 重新开始按钮。

界面不要求复杂，但应布局合理、文字清楚、操作正常。箭头成功飞出和发生碰撞时，应有基本的动画或视觉反馈。

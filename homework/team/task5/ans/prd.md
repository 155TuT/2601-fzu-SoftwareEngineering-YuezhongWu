## 一、产品主线与使用方式

### 1.1 产品定义

**从用户留下的生活材料中持续形成习惯与偏好模型，让下一次帮助少问重复问题、更符合当时情境，并能随反馈纠正。**

核心循环为：

**留下材料 → 整理事件、语义标签与证据 → 更新个人模型 → 在事项中使用 → 回收实际反馈。**

**首期形态是自带手机 App＋本地业务核心＋模型适配层。** 用户在应用和系统入口中记录、查看与纠正；核心在获准执行时处理，随时保存进度。前后端在代码和契约上分离，手机内通过模块调用协作。

交互采用记事本结构：记录聚合原文、附件、对话与相关事件，需要持续跟进时关联目标成为事项。Agent 结合本地算法生成可纠正的语义标签，使本地存储形成可按时间、人物、标签与状态检索的事件数据库。“Agent 标签”描述内容的语义，标签生成与个人偏好建模分别保留依据。

个人资料、习惯统计和偏好参数由本地核心维护。语言／视觉推理可接端侧模型或远程 API：远程模式标明发送范围与处理位置，完整端内模式另做断网验证。独立 CLI 用于测试与复用，MCP／HTTP 服务在扩展宿主上验证；长期服务部署到用户自管主机。

个人状态分为四类：

| 状态 | 含义 | 例子 |
| --- | --- | --- |
| 事实与经历 | 有来源、时间和主体的表达或观察 | 这次换乘花了 20 分钟 |
| 习惯 | 在已观察范围内反复出现的行为 | 工作日多在晚间学习 |
| 条件偏好 | 特定情境下的倾向与取舍 | 赶时间时愿意加钱减少换乘 |
| 当前目标 | 有期限、状态与执行责任方的要求 | 周五前买票，降到目标价时提醒 |

“内化”体现为规则、统计或参数的更新，并在后续任务中产生可检查的影响。通用语言／视觉模型理解材料，个人模型保存持续更新的用户状态。

### 1.2 用户、场景与价值

| 用户 | 任务 | 产品价值 |
| --- | --- | --- |
| 反复处理生活选择的人 | 选餐、通勤、购物、学习或运动安排 | 少解释旧背景，使用真实经验 |
| 为家庭或共同活动作安排的人 | 同时考虑不同人物与条件 | 认识归属清楚，条件可调整 |
| 已有个人 Agent 的人 | 换入口继续使用和更新认识 | 经验随用户复用 |
| 自部署与集成使用者 | 配置、维护和迁移服务 | 数据与接口可持有、可检查 |

饮食做深入体验验证，出行、消费、学习／工作、作息／运动检验通用性。菜谱、行程、报价和学习资料都是可选资源，事件可以独立保存。用户与竞品证据见 [research 第二、五节](research.md)。

例如，用户记下“加班晚间做饭太累，洗锅尤其麻烦”。系统保存经历与条件评价，后续逐步形成相应认识；下一次加班时调用这些依据，用户的实际选择与反馈再更新模型。这套流程同样用于出行投入或学习安排。

### 1.3 页面与交互

| 入口 | 主要任务 |
| --- | --- |
| 对话与记录：首页 | 打开即可输入，选择对话或记录模式后提交；继续原记录中的事项，补充材料与反馈 |
| 记录库 | 默认时间线；按记录本、语义标签、人物、时间、进行中或待回应筛选；打开统一记录详情 |
| 设置 | 智能与连接、记录与记忆、外观、数据与关于分组；开关与选项就地操作，复杂配置进入详情 |

首页顶栏保留记录库和设置入口，底部承载输入。记录本、标签与状态是同一内容库的组织和筛选方式；记录内维护正文、材料、对话、相关事件、目标与结果。完整入口矩阵见[信息架构](information-architecture.md)。

空库可以直接记录、在设置填写偏好或使用独立示例库。示例含至少 5 条饮食经历、3 个候选资源及其他四类场景的边界案例。回答旁提供依据和纠正，完整记忆管理位于“设置 → 记忆与偏好”。普通整理进度附在原记录上，需要回应时再显示提示。

界面统一显示“已保存、正在整理、等待条件、需要核对、已更新”。模型缺失、空间不足和权限变化给出原因与可执行操作，保留已输入内容。

### 1.4 项目标志与思维导图

项目名称为 **PebblePile · 叠石**。三块错位叠放的河石表达材料、认识与持续更新，俯视与侧视结合，保留自然轮廓和层间重叠。矢量标志与应用图标见 [assets](../assets/README.md)。界面保留用户原话，技术详情放在诊断页。

## 二、范围与功能需求

首期交付 **F01—F13**：双平台 App、本地资料与个人模型、可恢复处理、选定模型接入、场景协议、系统入口、CLI 与备份。F14 为适配验证；完整端侧推理通过 A29 后列入支持能力，外部 MCP／HTTP、Android 默认助理和宿主插件按 A35—A36 验证。实际订票支付、持续盯价、自动同步与复杂潜在表示后续扩展。

### F01：建立资料库与准备模型

首次打开创建本地库，文字保存、编辑、检索和明确设置即可使用。模型适配层支持端侧运行时或配置的服务 API；设置显示位置、版本、准备状态、费用与可用条件。M0 用同一中文任务确定首期路径和支持设备，完整端侧能力按 A29 单列。

断网时继续管理已有资料，需推理的任务保留待处理状态。采用远程 API 的版本明确标为“本地存储与个人状态＋远程推理”；称为“纯端内”的路径覆盖全部所需推理。

本地基础功能免费，代码与数据格式开放。远程服务作为可选配置，列出发送范围、提供方、费用与模型许可。

### F02：自然记录与资源导入

| 输入 | 首期范围 | 处理 |
| --- | --- | --- |
| 文字 | 单条最多 10,000 字符 | 原话先保存，按需分段和补充缺项 |
| 截图 | JPEG／PNG，单张最多 5 MiB，以中文印刷文字为主 | 保存图片，OCR 片段定位到原图 |
| 链接 | 公开静态 HTML，响应最多 2 MiB；普通文本及已注册 JSON-LD | 保存 URL 与内容快照；受限内容由用户分享文字／图片 |
| 系统分享 | Android 接收文字、链接、受支持图片；iOS 经快捷指令／应用入口交接 | 临时资源先取得持久副本或持续读取能力 |

来源、附件和任务引用提交成功后返回“已保存”。重复来源可定位已有记录；另一次真实经历可以单独建立事件。超限给出重选路径，保存失败显示实际状态。

第一条内容建立记录，后续对话和附件关联同一记录；记录本可稍后指定。顶栏下方用“对话／记录”页面级分段选择，切换保留草稿和记录上下文。记录模式先完成本地保存，是否继续抽取与打标签按自动整理设置执行；对话模式在保存后继续问答。提交采用图标按钮，可访问名称随模式为“发送”或“保存记录”。每次保存保留内容起源、来源版本和记录归属。语音入口调用系统听写，文字先进入可编辑草稿，再由用户提交；取消和权限拒绝保留原草稿。原型演示该入口，系统支持与隐私提示在实现时按平台验证。

### F03：记录组织、通用事件与资源版本

记录本采用浅层组织。记录聚合来源版本、会话、事件与可选目标；带目标和后续进展的记录呈现为事项。时间线、记录本列表、标签筛选和状态列表返回同一记录标识与详情。未抽取出事件的内容按记录时间回查；发生时间与记录时间分别展示。

事件保存主体、行为、对象、时间、情境及实际／计划等类型；资源引用可空。发生时间与记录时间、记录者与经历者分别保存，模糊时间保留精度。

资源保存类型、Schema、载荷、来源与父版本，编辑生成新版本。事件关联实际使用版本。支持检索、补记、合并重复事件与调整人物；合并保留来源映射，并重算受影响证据。

### F04：事件、语义标签与证据整理

提取人物、行为、情境、评价和来源位置，区分实际经历、计划、假设、转述、收藏及 Agent 生成内容。缺项和竞争解释保留待核对状态。

每条证据可打开原话或图片区域。输出经结构、引用、人物范围与版本校验后入库；无效输出保留原材料并报告失败。独立证据按事件计数，重复分享沿用同一来源关系。

Agent 提出主题、场景、行为与情境标签候选，本地算法按词表做同义归一、去重、结构校验和索引更新。标签定义保留命名空间、类别与归一名；指派保留记录或事件归属、起源、依据版本及位置、算法版本、置信度、状态与修订。低置信或竞争解释进入待核对，人工确认与排除优先。

标签支撑检索、内容关联与已启用规则的匹配。人物、时间、观察类型和目标状态仍由结构化字段表达；带有“旅行”标签的计划保留计划类型。自动标签的存在与事实成立、偏好形成及执行授权分别校验。

### F05：习惯、偏好与模型更新

个人模型保存明确设置、习惯统计、条件偏好、取舍参数和快照。“本人明确”与“根据经历推断”分别展示；用户可启停推断辅助，明确要求和当前条件优先。

首期候选阈值为：偏好至少两次独立实际经历，习惯至少三次观察且注明窗口与覆盖。一次明确表达可形成本人设置。推断经来源与冲突检查，并在用户启用后参与适用情境内的低风险排序。阈值在 M0 校验，后续调整随版本记录。

习惯记录频次、观察次数、时间分布和例外；条件模型比较规则计分与一种增量参数方法。共享参数附语义、单位与范围，领域和情境修正分别保存。算法与纠正规则见第三节。

完整管理入口为“设置 → 记忆与偏好”；回答旁的依据与纠正直达相关认识。自然语言中的“仅这次”与长期要求分别保存作用范围。

### F06：目标与任务上下文

目标保存要求、期限、状态和执行责任方；持续关注任务另存频率、最近／下次检查及数据有效期。报价、库存等动态资料带来源与采集时间。

目标关联原记录，候选、下一步、选择和后续反馈在同一事项中延续。用户从记录库的“进行中”“待回应”视图继续处理。上下文检索可以组合语义标签与时间、人物、事项范围，并回查实际来源。

按任务、授权和预算返回有效习惯、偏好、相关证据、必要反例、未知项与处理进度。自带 Agent 据此给出少量候选或计划，并解释来源；外部宿主可直接使用结构化上下文。

记录候选、展示顺序、特征、选择及所用模型／资源版本。确定性换算交给场景规则；编辑先预览再形成资源版本。后台监测由选定执行宿主承担，界面显示最近有效状态和等待条件。

### F07：实际结果与反馈

分别保存建议、用户选择、Agent 动作、执行回执与本人体验。结果标明发起者、观察方式、时间，并关联目标、决策或事件。

请求送达、页面变化与目标完成使用不同状态。未知执行结果先核对，再继续或重试；有副作用的操作使用宿主提供的幂等能力或状态查询。Agent 自选结果作为执行事实，喜好学习使用对应的本人表达与体验。反馈可离线补记，并触发局部更新。

### F08：纠正、停用与删除

支持自然语言或卡片纠正人物、时间、评价和条件。修改带基准修订号；冲突保留输入并显示当前版本。纠正立即停用受影响旧认识，再重算相关部分。

标签支持确认、添加、合并、排除与撤销人工覆盖。人工排除按稳定记录或事件标识及归一标签保留，重算时继续生效；用户可明确撤销。来源修订使受影响的自动指派失效，标签索引、事项匹配和待处理输入同步检查有效版本。

移出记录本或移除引用只调整组织关联。删除原记录或材料时，先预览跨记录引用、相关派生内容与处理任务的影响范围；来源的原记录归属与其他记录的引用分别保存。

停用控制参与查询；删除清理来源、附件及相关派生内容，并取消依赖任务。失去全部依据的推断撤回，仍有独立依据的部分重算。清理范围覆盖快照、索引、缓存和含正文的诊断；必要的无正文删除标记阻止迟到写入。用户保存的旧备份与外部副本在相应管理入口处理。

### F09：任务、预算与中断恢复

来源与适用的首个任务原子保存。识别、场景解析、标签归一、证据整理、模型更新和发布分别设置检查点。标识包含输入版本、阶段与算法版本，重复执行只提交一次。

记录保存、材料补充、本人反馈、纠正和到期检查是处理触发；生活事件是被整理的数据。已启用的场景规则可按有效标签、事项状态与人物范围匹配，匹配和任务入队在同一事务完成。规则标识包含场景命名空间、版本和规则键，触发幂等键包含目标记录与输入修订；执行前重查授权、预算、规则启用及输入有效性。

记录内显示相关进度，完整队列与预算放在“设置 → 智能与连接 → 处理”；标签与整理规则设置保存自动整理、启停、范围与预算。需要用户回应时提示到原事项。到期触发按实际运行窗口恢复，展示最近检查与等待条件。

初始预算：一次文本整理或查询最多 3 次模型调用，每次输入最多 4,096 token、输出最多 1,024 token；最多 8 次业务工具调用、120 秒累计活动时间。分段与重试共享父任务预算；图片 OCR、等待调度及用户等待另计。批量任务先展示总预算，达到上限保留进度。

前台查询与纠正优先，批量处理按电量、温度和系统机会调度。退后台先提交检查点；允许继续时处理有限批次，恢复前台时检查队列。暂停、失败、取消和等待持久保存，输入过期的迟到结果退出提交。远程请求也保存操作标识、预算与接收状态。

### F10：系统入口与核心接口

iOS 提供“记一件事”“找回经历”两个 App Intents／App Shortcuts 动作；Android 提供系统分享。短操作保存后返回回执，后续整理进入队列。

业务核心提供进程内 API 和可独立运行的 CLI，支持记录、上下文、结果、纠正与任务查询。CLI 用于开发验证、批量处理和服务封装，具有结构化输出和退出码。

MCP／HTTP 与宿主钩子在 F14 扩展中复用同一契约。接入须同时验证宿主协议、身份授权、可达路径和运行时间窗口；手机端首期通过系统调度的动作入口完成外部触发。

### F11：备份、恢复与迁移

备份包含记录本、记录与会话归属、来源、附件、事件、标签定义／指派／人工修订、证据、个人状态、目标、决策／结果、整理设置、场景与算法版本及校验清单；连接密钥与临时上下文单独管理。

恢复先在新库校验格式、大小、路径、附件和引用，预览后原子切换。损坏、取消或空间不足保留原库。双平台共用格式；缺场景包时保留载荷与通用关系，算法不匹配时重建派生结果。旧备份明确显示时间与内容范围。

### F12：授权、部署与诊断

所有者管理资料库、人物、来源范围及客户端读写权限。资料库标识选择数据，认证身份决定访问权。外部 Agent 的推断、本人的明确设置和删除授权分别处理。

首期由手机库确认有效修订。独立服务扩展另有数据目录、启动停止和备份路径；切换权威库采用明确迁移。模型与连接设置说明外发范围，撤销后拒绝后续访问。诊断记录版本、调用量、延迟、预算与失败阶段，普通日志使用引用和状态。

### F13：场景协议与通用性

场景包定义命名空间、Schema、对象、单位、抽取样例、特征映射、约束、结果及测试案例。公共数据与接口稳定，领域字段单独校验。未知场景先保存原材料，待解释后补充结构。

场景包同时维护标签类别、规范词表、同义映射和可启用处理规则。跨场景标签通过明确的语义映射关联；版本变化保留旧指派依据并重建受影响索引。首期提供受控词表与人工扩充入口，算法评估覆盖近义词、歧义、否定、计划和生成内容。

提供饮食、出行、消费、学习／工作、作息／运动的轻量协议。禁用饮食包后，其他场景仍完成记录、建模、使用、反馈、纠正与迁移。共享认识保留语义映射和适用范围，按留出场景检验。

### F14：采集与宿主适配验证

Android 识屏原型采用默认数字助理接口，作为用户主动选择的入口：用户唤起后取得系统提供的文本／图像，补充体验并选择保存片段。统一返回观察 ID、来源应用、采集时间、内容、完整性及失败原因。结构化文本优先，OCR／视觉理解按需处理；空值、关闭、替换和迟到回调均有明确状态。

临时快照用于本次任务；符合记录意图或已启用采集规则的片段，取得持久副本后进入 F02。持续 GUI 观察与动作由执行适配器承担，按观察号验证状态，动作后回读，支持用户接管。

外部服务原型在明确运行的测试宿主上提供 MCP／HTTP，宿主插件调用统一核心，工具卡呈现依据与纠正。长处理返回任务 ID，按宿主预算查询进度；权限、原生界面与连接能力按实际支持情况选择。扩展验收见 A35—A36；核心记录和模型能力按 F01—F13 交付。

## 三、个人模型与数据规则

### 3.1 模型、程序与用户的分工

| 环节 | 模型／Agent | 确定性程序 | 用户 |
| --- | --- | --- | --- |
| 理解材料 | 提取、提出条件与竞争解释 | 保存、校验结构和引用 | 补充关键缺项 |
| 组织标签 | 提出有来源的分类与语义候选 | 词表匹配、归一、去重、状态检查与索引 | 确认、改名、合并或排除 |
| 形成认识 | 提出习惯与偏好候选 | 去重、证据计数、统计与参数更新 | 确认或纠正 |
| 使用与反馈 | 选择上下文、解释候选、组织任务 | 授权、预算、状态检查与回执 | 作出选择、接管和评价 |

领域定制资产包括场景 Schema、提示词、特征与单位、证据规则、工具契约及测试案例。来源为获准用户材料、团队案例、[Schema.org Recipe](https://schema.org/Recipe)等领域结构，以及 [research](research.md) 中的论文、平台文档与源码；每项记录版本、用途和复核人。

### 3.2 模型更新原则

规则、习惯统计和一种增量参数模型作为首期比较。取舍参数由共享部分、领域修正与情境修正组成；共享程度通过语义映射和留出验证确定。观察覆盖、可得选项、展示次序与行动发起方式共同参与解释。

模型快照保存认识版本、统计／参数、证据依赖、特征／算法版本和数据水位。候选快照校验后发布；纠正或删除先停止受影响部分使用，再按有效证据局部重算或从检查点重放。历史决策保留修订关系，已删除正文同步清理。

### 3.4 一致性与状态

| 对象 | 状态规则 |
| --- | --- |
| 来源 | 保存即可回查；修订生成新版本；删除保留必要的无正文标识 |
| 记录与标签 | 记录归属可调整；标签指派为待核对 pending、有效 active、人工排除 rejected、已撤回 retracted；人工覆盖与依据修订分别保留 |
| 习惯／偏好 | 待核对、有效、冲突、已取代、已撤回；起源和暂停使用另记 |
| 目标／动作 | 目标为进行中、等待、完成、取消、到期；动作另记请求、验证、失败或待核对 |
| 快照 | 候选、有效、已取代、受影响停用；查询绑定一致版本 |
| 任务 | 排队、运行、完成；可进入等待、待核对、失败、取消或输入过期 |

阶段结果先写入工作区，提交时重查输入、权限、取消与修订，再原子发布。查询使用已发布版本，并提示新材料处理进度；旧索引仍经过有效性过滤。来源变化沿依赖传播到参数、快照、索引和上下文缓存。

## 四、软件架构与接口

### 4.1 模块结构


移动端采用应用内分层：界面和系统入口调用业务核心，核心管理学习与一致性，持久队列响应系统调度。模型 API 是推理依赖，个人状态由本地核心保存。场景、采集、执行与服务封装通过独立适配层扩展。

首期优先验证事务数据库加附件目录、全文检索的轻量实现，向量检索按收益加入。感知模型与个人参数分别版本化，模型调用由统一预算控制。SQLite、运行时与客户端框架在 M0 用同一链路确认。

### 4.2 关键契约

| 契约 | 最小内容 |
| --- | --- |
| 摄取材料 | 操作 ID、来源／版本、采集方式、时间、原文／附件、可选人物与场景；返回保存回执和任务 ID |
| 记录与标签 | 记录／记录本标识、关联来源／事件版本、标签命名空间、归一名、指派起源、依据、算法、状态及人工修订 |
| 屏幕观察 | 观察 ID、来源应用、采集时间、文本／图像、范围、完整性、可用状态 |
| 模型快照 | 资料库修订、有效认识、参数、证据依赖、算法／特征版本与处理水位 |
| 任务上下文 | 状态、正文或结构化条目、精确证据引用、快照、预算、遗漏、未知项与处理进度 |
| 使用与结果 | 宿主、任务、所用快照和条目；动作、回执、实际结果及本人反馈分别记录 |

上下文区分 `ready/empty/unavailable`。传输设置 UTF-8 字节上限，推理按实际 tokenizer 计量；两者分别检查。接入方按资料库、授权范围、查询、快照及预算标识缓存，修订或撤权后失效。

跨工具共享需要：绑定同一权威库、读取有效快照、通过接口写回、下一轮重新核对修订。“材料已保存”“模型已更新”“宿主已使用”分别记账；宿主回报所用快照和条目，缺少回执时保留未知。普通查询读取已有结果，复杂整理进入持久队列。

### 4.3 业务工具

| 工具 | 作用与关键返回 |
| --- | --- |
| `record_experience` | 保存材料或经历，可指定记录、记录本与仅记录意图；返回记录、来源、事件和适用的整理任务 |
| `query_records` | 按时间、人物、记录本、语义标签及事项状态组合检索，返回统一记录引用与匹配依据 |
| `update_record` | 修改记录标题、归属与关联，保持来源正文及其版本关系 |
| `revise_tags` | 确认、添加、排除标签或撤销人工覆盖；返回有效修订与受影响范围 |
| `query_context` | 按任务、情境与预算供给有效认识和证据 |
| `propose_preference` | 提议认识；返回证据校验、冲突与推断状态 |
| `update_goal` | 在原记录中新建或更新要求、期限与执行责任方 |
| `record_outcome` | 回写动作、观察、回执及实际评价 |
| `revise_memory`／`delete_memory` | 按基准修订纠正或删除，返回影响范围 |
| `get_task`／`control_task` | 查询、继续或取消，返回阶段与剩余预算 |
| `get_capabilities` | 返回协议、场景、处理位置及入口能力 |
| `export_data`／`restore_data` | 导出状态、恢复校验与预览 |

身份与资料库范围由认证上下文确定。写入带操作标识，修改带基准修订；重复请求返回原结果，冲突保留当前版本。查询携带权威实例、资料库、`revision`、快照与 `processedThrough`。

错误区分输入不支持、权限、版本冲突、模型不可用、预算、资源不足、处理失败和取消，返回可重试状态及下一步。

### 4.4 移动端运行与扩展

| 形态 | 本版选择与条件 |
| --- | --- |
| 自带 App＋本地核心 | 首期基线；前台及时处理，后台按系统机会继续，中断后恢复 |
| 远程模型 API | 首期可选推理路径；发送获准片段，处理断网、超时和迟到结果，本地维护个人状态 |
| 完整端侧推理 | 独立能力验证；全部所需模型准备好后通过 A29，再公布支持设备 |
| Android 默认助理 | 入口原型；系统维持轻量服务，重处理与交互／任务调度分开，测切换助理和进程重建 |
| 外部 Agent 服务 | 扩展；持续服务优先用户自管主机，手机临时窗口按明确可用条件试验 |

普通 iOS App 退后台会进入挂起；Android 前台服务有可见任务、类型和调度约束。首期的可靠性承诺是保存与恢复。官方依据见 [research 5.2](research.md)。Siri／App Intents 和 Android 系统入口在各自允许的执行窗口调用核心。

服务扩展使用选定 MCP 传输与认证。PC 作为服务和测试宿主，手机远端服务协同另含网络、缓存与同步工程。

跨工具契约借鉴 PowerContext，Android 采集借鉴 Eta 的公开系统接口，宿主候选优先试接 dsh-go 插件。三者的源码依据、条件与许可集中在 [research 第四节](research.md)。M0 比较最小原型的有效信息量、资源和维护成本，再确定复用深度。

### 6.2 效果对照与目标

B0 为原文加混合检索，B1 固定 Honcho 或 Hindsight，B2 为本项目。36 题按来源与事件、习惯与覆盖、条件偏好、目标与结果、变化与纠正、跨场景迁移各 6 题组织，至少 12 题取自获准真实材料。实验配置、数据切分与消融见 [research 第六节](research.md)。

固定材料、时间顺序、候选、回答模型、信息、预算和硬件；内部模型或部署不同的完整系统结果单列。三次均通过才计为稳定通过，两人隐藏组别评分。成本包含写入、整理、检索和回答。

关键错误包括主体错归后当作本人设置、编造依据、绕过已知限制、使用已撤回证据、虚报保存或执行成功、错误迁移为明确限制。允许保留题目规定的未知项；主观喜好以本人反馈与后续选择判断。

| 编号 | 设计目标 |
| --- | --- |
| G01 定制收益 | B2 相对 B0，人工纠正次数配对中位数降低 ≥20%，完成率不降 |
| G02 轻量使用 | 至少 6／8 人独立完成两轮任务；记一条简短经历、第二轮找回相关经历各 ≤1 分钟 |
| G03 经验复用 | 第二轮相对原有方法，重复说明条目中位数降低 ≥30%，操作时间降低 ≥20%，完成率不降 |
| G04 资源回报 | B2 达到 C05，稳定通过率与 B1 相差 ≤5 个百分点时，写入加查询总 token 降低 ≥20% |
| G05 跨场景收益 | 留出场景前五次任务中，相对同算法仅用目标场景数据，补充次数配对中位数降低 ≥20%，完成率不降，错误迁移单列 |

G01—G05 报告实测值与样本，安装准备单列。失败与放弃计入完成率分母，零基线报告绝对变化；资源同时报告延迟、内存和能耗。目标未达时调整收益表述。

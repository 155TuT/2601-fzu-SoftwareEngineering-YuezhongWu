## 3. 对调研的直接约束

| 聊天依据 | 明确的方向 | 在调研中的落点 |
| --- | --- | --- |
| Q02、Q05、Q08 | 主目标是个性化的本地菜单管理；原文对调整流程着墨过重 | 调整标题、市场机会、产品定位和核心验收任务 |
| Q09—Q12、Q15 | 主要材料由用户主动导入；“先按个人特点自动生成菜单”的理解未获认可 | 将导入、整理、保存、检索设为基础；不要求首次使用先生成一餐计划 |
| Q04、Q14 | 分析口味并沉淀个性化数据，用于推荐 | 单列偏好证据、候选确认、推荐解释和反馈复用 |
| Q03、Q15 | 菜谱可随生活条件变化，用户可以寻求一道菜的调整灵感 | 保留用户触发的调整建议、版本差异和采纳入口；完整排餐与执行调度降为扩展 |
| Q14 | 用户接入的 Agent 在本地按团队编写的工作流运行 | 区分软件管理能力、领域工作流、用户 Agent 接入和数据存储；原型需检验本地链路 |
| Q16 | 可以提供基本菜谱列表；Samsung Food 是明确提出的参考对象 | 补充无私人数据时的体验入口，研究其收藏、发现与个性化能力的组织方式 |

## 4. 尚未由聊天确定的内容

- “本地”的具体部署、存储格式、同步方式，以及模型推理是否也在本机。Q14 支持本地工作流与个性化数据沉淀，不能据此直接宣称全链路离线或零外传。
- 用户 Agent 的具体产品、接入协议、兼容范围、运行权限和配置方式。首期接通一种适配方式，是本次调研提出的实现建议。
- 基本菜谱列表的规模、来源及推荐排序规则。Q16 是可选方向，没有给出已确定的数据集或授权。
- 目标用户样本、偏好识别准确率、推荐效果和长期使用价值。聊天不提供这些结果。
- Q01 中的疾病、生理期和来访者是提问中的举例，没有被逐项确认为必须实现的服务；不能据此增加医疗或健康干预承诺。

## 5. 本次修订映射

| 原调研重心 | 本次修订 |
| --- | --- |
| 围绕一顿饭协调条件、采购和执行 | 以用户的本地菜谱库与持续个性化管理为主线 |
| 菜谱管理是基础，变化处理才是 Agent 重点 | 整理导入材料、识别偏好、解释推荐、积累个人版本共同构成 Agent 价值 |
| 默认两端使用同一后端 Agent 服务 | 提出本地管理服务与用户 Agent 适配方案，单列模型调用和同步边界 |
| 必须完成一餐计划、购物清单、厨房执行和临时变更 | 优先完成导入、管理、推荐、按需调整、反馈沉淀；排餐与采购执行按后续证据扩展 |
| 主要验证改人数与缺料后的联动 | 增加冷启动、收藏与偏好区分、个性化解释、版本保留、记忆撤销、本地持久化与 Agent 故障测试 |

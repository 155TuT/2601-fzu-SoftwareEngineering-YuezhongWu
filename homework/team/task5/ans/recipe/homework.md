## 团队展示

### 队名

你所热爱的就是软件工程

### 具体规划

我们的项目是 **个性化本地菜单管理软件**，希望做一个更懂你的菜谱小助手。“个性化”由我们编写的 Agent 流程、个人偏好建模算法、作为核心的用户本地数据和改动共同保证体验。核心用户是刚开始独立生活、仍需参照菜谱的做饭新手，也期望涵盖家庭里只是偶尔做饭、仍需菜谱交接的不够熟练的人。我们想让用户在手机上把找到的菜谱整理成自己的做法，做完留下经验，下次打开时接着用。

我们目前梳理了 Recipe Keeper、ReciMe、Samsung Food、Paprika 和 Mealie 等有力竞品的公开资料，这些产品覆盖导入、分类、份量调整和部分个性化能力，而我们重点关注了其中从中文材料校对到个人做法复用的操作成本。现阶段的依据来自竞品资料、团队讨论和答辩反馈；下一步将招募至少 8 位符合条件的用户，观察他们如何收集、修改和再次使用菜谱，再据此调整功能优先级。

我们的首期产品将围绕 **收进来 → 改成自己的做法 → 做后记一句 → 下次直接复用** 展开，重点做好三件事：

1. **收集时少一点抄写。** 用户粘贴文字、导入受支持的视频、网页或选择清晰菜谱截图，得到带来源和缺项的草稿，在原文旁完成校对。
2. **调整时看得懂改了什么。** 根据口味、食材和份量要求，联动调整配料与步骤，展示原因和前后差异，由用户保存个人版本。
3. **下次使用时记得上次经验。** 一句“这次偏咸，下次少放酱油”关联到当次版本；再次查看、调整或选菜时带回适用记录，长期偏好由用户确认和纠正。

领域定制将围绕菜谱结构、食材别名与状态、用量换算、偏好范围和配料与步骤关联展开。团队整理带来源和版本的规则及案例，让 Agent 在预设工作流中完成材料理解、偏好分析、推荐解释和单菜调整。手机程序负责资料检索、确定计算、版本检查和确认后的保存。我们希望由此减少用户查找上下文、重复说明口味和手工整理建议的步骤。

项目期望面向 Android、iOS，核心操作、资料存储和工作流都在手机端完成，模型能力通过 API 接入。双平台原生开发与跨平台开发将在真机原型验证后选择，PC 作为可选扩展。基础管理完全本地且免费，代码与领域规则开源，模型调用费用和课程测试额度在接入时说明。

## 需求分析文档

我们当前的产品需求文档已按课上老师的反馈尝试进行了一定的重构，目前仍处于需求评审阶段。本文档作为我们团队开发、演示和验收的共同依据使用，围绕做饭新手的两轮使用展开，规定文字、清晰截图和受支持网页的导入范围，以及个人版本、偏好确认、推荐、调整、反馈和备份恢复等核心功能。

方案采用手机界面、端内业务与本地资料库、领域工作流、远程 API 的结构。普通管理操作离线可用，联网任务保存进度并支持恢复；来源、个人版本和反馈保持关联，用户可以查看、修改或撤销偏好。文档同时说明领域知识来源、模型与程序的分工、工具接口和两种移动端开发方案的选型依据。

结课按 **C01—C06** 检查交付：完成至少 8 人访谈和至少 8 人两轮试用，两轮间隔至少 24 小时，至少 4 人按保存版本真实试做并反馈；Android、iOS 真机通过 26 个功能场景与 8 项非功能要求；提供可访问的发布入口、两平台安装／测试方式和开源材料。人工纠正次数、手机操作耗时与经验复用收益另按 **G1—G3** 报告，用通用模型对照与软件使用对照检验产品亮点。
